# Working on datacube

Datacube is a small speedcubing timer and practice log. Keep the code easy to read and the app easy to use. A new option should solve a problem people actually have while practicing. Keep replies direct. English or Brazilian Portuguese is fine.

## Where things live

- `frontend/index.html` and `frontend/src` are the editable frontend. Vite generates `frontend/dist`. Keep it out of Git.
- `frontend/src/timer` owns the timer engine and its controls. `analytics`, `history` and `import` have their own code and tests.
- `frontend/src/styles/main.css` holds the theme and responsive rules. `i18n.ts` contains interface strings. `icons.ts` is the entry point for Lucide icons.
- `backend` is FastAPI and SQLModel. Put database changes in `migrations` and keep SQLite support. `cube-database` holds the source catalogs used for suggestions.

## Interface

Use the existing dark palette, Roboto Mono, icons, and compact rounded controls. Keep new panels and plots mostly borderless. Give touch controls at least 44px of usable hit area even when the painted box is smaller. Use mouse-only hover styles where touch would leave a sticky highlight. Preserve keyboard focus and dialog dismissal.

Keep labels lowercase and short in all three languages. Cube model names, scramble notation, user labels and numeric formatting keep their own spelling and case. Preserve the two-line wordmark, the Portuguese dados/cubos treatment, and the existing header layout. Keep old storage keys and the session cookie name for compatibility.

Check narrow phones as well as desktop. Normal-size dashboards should fit the viewport. Short screens can scroll where needed to keep charts readable. Use external Chrome for browser checks.

## Timer, history and accounts

- Use `performance.now()` for timing and animation frames for display. Space or a pointer hold starts preparation. The hold stays at 400 ms. Releasing once ready starts the solve. During a solve, a pointer press or ordinary key stops it. Keep the timer target large and give controls priority. Restore timer focus after returning to the timer or closing its panels on desktop.
- Save raw milliseconds and a UTC timestamp. Capture the event, cube, optional scramble and fixed tag at start. Save immediately on stop with the same client UUID on retries. Pending saves live in browser storage and stay isolated by account. Preserve them when a request fails or the solve quota is reached.
- Scrambles are optional, event-specific and generated by cubing.js. A valid scramble is required before starting while they are enabled. Keep their text exactly as generated and keep the timer in place when notation wraps.
- History pages through all owned solves in batches of 50. Keep the date filter above the scrolling list. Edits save on close and failures keep the editor open. Cube labels and tags for new entries are capped at 12 characters. Catalog IDs distinguish models even when their handles match. Use the authenticated session for ownership and render user-supplied text as text.
- Keep credentials hashed with Argon2 and store session token hashes only. Preserve per-account browser preferences and server-side first-login acknowledgment. Mutating API calls use the request header, and account-scoped writes also check the account header. Ignore stale async results after an account change.

## Analytics

- Overview and Compare share one event and the date range. Default to 3x3. Keep filter choices when switching views. Overview’s cube and tag filters narrow each other. Compare keeps independent checkbox selections, and clearing all options means an empty chart.
- Analytics uses the complete account history. Defer expensive updates while hidden, then refresh the active view when reopened. Recheck rolling ranges and preserve valid selections. History pagination is separate.
- Apply +2 when computing effective times. Count DNFs in solve totals, omit them from numeric distributions, and retain them in rolling-average windows under the existing trim rules. Keep the current outlier handling and axis behavior.
- Use the same evenly spaced solve positions for Times dots and the rolling-average lines, up to 600 on mobile and 1,200 on desktop. Keep every personal best. Statistics use the full filtered data. Preserve the current draw order and responsive stroke widths.
- The overall activity grid counts all saved solves by local day, including DNFs, regardless of Overview filters. It sits above Distribution on desktop and on the third stats page on mobile. Compare uses median-sorted boxplots. Keep tooltip percentages based on the relevant labeled solves for the event and date range, independent of checkbox selections.

## Imports and backups

Native backups use versioned JSON and portable solve IDs that are separate from local row IDs. Keep full timestamp precision, raw times, scrambles, penalties, tags and file-local event and cube references. Preview and restore validate the original bytes up to 32 MiB. Restore is atomic and adds missing IDs only. Existing records stay as they are, even if their exported values were edited. Export includes the full history and can exceed the restore size limit.

csTimer has its own parser and per-session assignment flow. Keep the 10 MiB and 50,000-record limits and its existing duplicate matching rules. Apply the account quota in the same transaction as the inserts.

## Server settings

Set these in the backend environment before starting the server.

| Variable | Default |
| --- | ---: |
| `DATACUBE_SOLVE_LIMIT` | 50,000 solves per account |
| `DATACUBE_LOGIN_IP_PER_MINUTE` | 10 |
| `DATACUBE_SIGNUP_IP_PER_MINUTE` | 5 |
| `DATACUBE_BULK_ACCOUNT_PER_MINUTE` | 6 |
| `DATACUBE_BULK_IP_PER_MINUTE` | 30 |
| `DATACUBE_BULK_CONCURRENT` | 2 per worker |

The request limits use a rolling minute and return `429` with `Retry-After`. One bulk operation can run per account. Timer saves are separate from the bulk limits. Counters and slots are per process. Use shared atomic limits if they need to apply across workers.

Use the connection IP by default. Set `DATACUBE_TRUSTED_PROXIES` only for explicit proxy addresses or CIDRs that supply a trustworthy `X-Forwarded-For` chain. Run Uvicorn with `--no-proxy-headers` so the app sees the real peer. Keep Turnstile secrets server-side and require Siteverify before creating an account when protection is enabled. Use `COOKIE_SECURE=true` behind HTTPS.

## Before shipping

Run `npm test` and `npm run build` from `frontend` and `.\.venv\Scripts\python.exe -m pytest backend/tests` from the root on Windows. Use synthetic solves or a temporary database for browser and import checks. Back up existing data before migrations.

Keep databases, exports, credentials, private host settings, logs and build output out of Git. Review the staged files and the unpublished commits before pushing. Commit or push only when requested.
